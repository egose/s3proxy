### Task PROBE-01: Separate Local Probes From Virtual S3 Resources

Status: completed

Kind: defect

Priority: P1 — object writes can receive HTTP success with no backend mutation.

Suggested agent: HTTP/addressing boundary implementer.

Dependencies: none.

Primary ownership: `internal/httpapi/handler.go`, `internal/requestctx/context.go` if a shared host helper is needed, focused tests, health integration test, health/API/deployment/design documentation.

Finding: handler compares decoded `URL.Path` to `/healthz` and `/readyz` before parsing/auth for every method, host, and query. On a configured virtual bucket host these are ordinary object keys, yet PUT returns `200 ok` without writing, DELETE without deleting, and GET without reading. Encoded unreserved spellings also collide. Path-style ListObjectsV2 for buckets named healthz/readyz is replaced by `ok`. This skips auth but does not demonstrate unauthorized access or backend mutation: the backend is never called. The confirmed harm is false acknowledgment/unavailable resources, with potential application data loss if a client discards data after trusting PUT success.

References:

- `internal/httpapi/handler.go:96-107` (`ServeHTTP` probe early returns).

A local probe is only **GET**, exact `URL.EscapedPath()` `/healthz` or `/readyz`, no Authorization header present, empty RawQuery with ForceQuery false, and host not recognized as a virtual bucket host under configured addressing rules. Every other request uses the normal S3 pipeline, not a new probe-specific 405.

### Task QUERY-01: Reject Malformed Queries Without Using Partial Decodes

Status: completed

Session: isolated QUERY-01 implementer; PROBE-01 completion evidence confirmed before starting. No delegation.

Kind: defect

Priority: P2 — unsupported selectors can disappear before supported operations execute.

Suggested agent: request validation/auth/backend boundary implementer.

Dependencies: PROBE-01 (shared handler/requestctx paths and malformed probe-query handling).

Primary ownership: strict reusable query parsing boundary, `internal/requestctx`, `internal/auth`, `internal/backend/s3`, handler error mapping, focused tests and API/design documentation.

Finding: `URL.Query()` ignores `url.ParseQuery` errors, retaining partial valid pairs. Consequently DELETE `/bucket/key?versionId=%GG` or `?tagging=;ignored` classifies and forwards ordinary DeleteObject; ListObjectsV2 with malformed `prefix` loses the client scope within its configured namespace. Header/presign signing also uses lossy parsing, so adding a discarded malformed pair to a valid signed request need not invalidate its signature. This is malformed-input acceptance/reinterpretation, not credential forgery, cross-tenant access, or execution of the unsupported API itself. Existing unsupported-query tests use successfully decoded queries.

References:

- `internal/requestctx/context.go:37-45` (`FromRequest` uses `URL.Query`).
- `internal/s3ops/classify.go` (`Classify`, `IsMultipart`).
- `internal/httpapi/handler.go:107-155` (parse/classification/auth ordering).
- `internal/auth/verify.go` (`Verify`, `verifyQuery` and signer reconstruction).
- `internal/backend/s3/client.go:89-102,324-330` (classification and outbound query rebuild).
- `internal/s3ops/classify_test.go` (ParseQuery errors rejected by fixture, not tested in runtime); `internal/backend/s3/operation_boundary_test.go`.

Direct backend execution must reject before source-body reads, signing or network; standalone SigV4 authentication must reject before signature normalization/body verification. Keep errors/logs free of raw query/credential values and parser excerpts.

Exercise malformed names and values, percent truncation/invalid hex, raw semicolons, valid+invalid duplicate controls, unsupported selectors and a malformed listing prefix. Signed fixtures should be valid before appending malformed segments. Record what failed on old code.
