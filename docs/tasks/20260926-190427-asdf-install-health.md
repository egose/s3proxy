### FINAL-06 Findings And Corrections

- **F1 — P1, fixed: publication could copy across filesystems and leave incomplete installed bytes.** On entry, `bin/install` created staging under `dirname "$install_path"`. An install directory that is a mount point, or a symlink to another filesystem, puts the source and target of `mv` on different devices. A copy-fallback failure can leave partial `bin/s3proxy` in the destination even though extraction was staged correctly and the process returns failure. The previous `mv` fake only exited before writing, so it did not detect this. Merely documenting cross-filesystem nontransactionality did not meet INSTALL-02 R2–R3's no-incomplete-installed-binary contract.
  - Regression first: added a bounded fake device boundary at the install directory. Its `mv` writes `partial copy` and exits 76 only when the source is outside that boundary; moves within the boundary delegate normally. Against the entry implementation, the real installer exited 76, cleaned its stage, but left incomplete destination bytes. The suite exited 1 with **4 failed assertions / 33 cases** (status, missing success, wrong installed bytes, wrong mode).
  - Correction: create the installation directory before staging, then use `mktemp -d "$install_path/.s3proxy.install.XXXXXX"`. Staged `bin` and published `bin` now share the destination filesystem, including when the install path resolves through a symlink. The existing collision guard, extraction flags, explicit file validation, chmod and failure propagation remain intact. Updated README to describe enforced same-filesystem placement. Failed preparation may still leave an empty installation directory; cleanup failures and post-publication rmdir failures retain the documented behavior.
  - Updated fault guards and cleanup assertions to cover both old and new stage locations, keeping the original regression safe to run in disposable copies. Added a successful install-path-symlink case that preserves the link and caller sentinel. Final **34 installer cases pass**, including the fake cross-device boundary with exit 0 and complete mode-0755 bytes. Actual mounts/cross-device I/O were not exercised; the device boundary is mocked, while directory/symlink operations and normal rename publication execute real local tools.
- **F2 — verification gap, corrected: successful-looking pipeline output was incompletely covered.** Added a `cut` fake that returns the real valid verbose-tar type output and then exits 71. The installer aborts with no success/publication, proving the pipeline's rightmost failure is observed as well as the existing failing-tar case. Added `tests/asdf-download-faults.sh` to the existing `make test-asdf` entry point: **18 cases** cover curl archive/manifest failures after writing valid-looking bytes; actual `sha256sum` and `shasum` results followed by exit 75; missing, duplicate, malformed and mismatched manifest records; normal and `*filename` manifests.
